# 🏥  **Clinical Stage Predictor**

ML-сервис для определения клинической стадии заболевания $(1–7)$ на основе данных о мобильности, мышечной силе и клинических наблюдениях. Предназначен для врачей: интуитивный интерфейс, мгновенный расчёт и объяснение решений модели.

## **Ключевые возможности**

- **Точное предсказание** на основе XGBoost с балансировкой классов (SMOTE). 

- **Интерпретируемость**: модель показывает топ-3 признака, повлиявших на результат.

- **Веб-интерфейс**: готовая форма ввода от Streamlit без настройки кода.

- **Docker-развёртывание**

## **Технологический стек**

`Python 3.12` | `FastAPI` | `Streamlit` | `XGBoost` | `SHAP` | `Docker Compose`


### 🔹 Краткое описание компонентов

| Компонент | Назначение |
|-----------|------------|
| `api/preprocessing.py` | Преобразует «сырые» данные от врача в числовые признаки|
| `api/main.py` | REST API: принимает JSON, вызывает препроцессинг, делает предсказание, возвращает ответ|
| `frontend/app.py` | Веб-интерфейс: форма ввода, отправка запроса к API, отображение ответа|
| `src/train.py` | Обучение модели: загрузка данных, кодирование, SMOTE для балансировки, StratifiedKFold|
| `models/*.pkl` | Готовые артефакты для инференса: модель, порядок признаков, медианы для импутации |

## **Запуск**

```bash
docker compose up --build
```

После сборки откройте:

- Интерфейс: http://localhost:8501

- API Docs: http://localhost:8000/docs

## **Использование API**

Эндпоинт: `POST /predict`

Формат запроса: JSON с параметрами пациента (полный список доступен в `/docs`). Пропущенные поля допустимы и будут обработаны автоматически.

Пример ответа:

```json
{
  "stage": 5,
  "confidence": 0.84,
  "probabilities": {"1": 0.02, "2": 0.05, "...": "...", "7": 0.01},
  "shap_explanation": [
    {"feature": "Способность пациента к ходьбе и бегу", "value": 5, "impact": 0.41},
    {"feature": "Контрактуры голеностопных суставов", "value": 1, "impact": 0.12},
    {"feature": "Возраст", "value": 11.0, "impact": 0.05}
  ]
}
```

## **Особенности обработки данных**

- Стадии: модель обучается на кодировке $0-6$, API автоматически возвращает клинические стадии $1-7$.
    
- Пропуски: если пациент не ходит или не может пройти $10$ м, пропуски в тестах на прыжки/лестницу заменяются на худшие значения (клинически обосновано). Остальные пропуски заполняются медианой.
    
- Мультилейблы: Контрактуры и кардиомиопатия разбиваются на бинарные признаки через `MultiLabelBinarizer`.
    
- Диапазоны: Значения вроде "$2-3$" или "от $350$ до $500$ м" автоматически заменяются на среднее.

Полная обработка данных приведена в `../notebooks/data_preparing.ipynb`.

Проект создан в учебных/исследовательских целях. Для клинического использования требуется валидация на расширенной выборке.
